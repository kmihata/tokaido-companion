# Footpath handoff test

Diagnostic files, generated by `../scripts/make-footpath-test-gpx.mjs`.
Regenerate with `node scripts/make-footpath-test-gpx.mjs`.

These exist to answer one question before any export code is written: **can a
GPX file produced by this app reach Footpath on an iPhone and be used?**

The coordinates are approximate placemarks near Odawara and across the
Miya–Kuwana bay. They are not roads. This tests file plumbing, not navigation.

| File | Isolates |
| --- | --- |
| `TEST-A-track-with-waypoints.gpx` | `<trk>` with elevation and 3 waypoints — the common export shape |
| `TEST-B-route-element.gpx` | `<rte>` instead of `<trk>`, no elevation |
| `TEST-C-gap-two-segments.gpx` | **Two track segments 21 km apart.** Does Footpath bridge the gap? |

| `TEST-D-two-track-elements.gpx` | Two separate `<trk>` elements — kept apart, or joined? |

**Results are recorded in `../HANDOFF.md` under "Footpath handoff".** Summary:
C was bridged into one line across the bay; D was kept apart as two routes in a
named list. The export shape is therefore one file per day with several `<trk>`
elements, never several `<trkseg>`.

This folder can be deleted; the generator reproduces it.
